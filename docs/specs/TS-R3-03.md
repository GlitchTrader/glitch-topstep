# TS-R3-03 — Reliable trade outcomes and learning-grade execution evidence

**Issue:** [#70](https://github.com/GlitchTrader/glitch-topstep/issues/70)  
**Priority:** P0 (publication) / P1 (v1.1 enrichment)  
**Gateway version target:** 0.1.3+  
**Profile contract:** `glitch.topstep.trade_outcome.v1` → **v1.1** (backward compatible)  
**Depends on:** TS-R3-01 (publisher exists but does not fire reliably in live PRAC)  
**Profile consumer:** `glitch-topstep-hermes-profile:GTHP-012`

## Problem

TS-R3-01 implemented the publisher, `/outcomes`, and Hermes `sync_gateway_outcomes()`, but production PRAC sessions after 2026-08-03 show:

- `data/trade-outcomes.jsonl` absent;
- `GET /outcomes` returns `count=0`;
- zero `trade_outcomes_published` events in `data/events.jsonl`;
- Hermes `state/outcomes.jsonl` absent;
- learning worker reports `canonical_outcomes: 0` and `trade_episode_count: 0`;
- receipts and SQLite execution state confirm real armed fills (`entry_open_with_proven_protection`, `close_contract_submitted`).

The Hermes supervisor can show `active_trade_state` while positioned, but cannot produce `trade_episode.v1` without canonical completed outcomes.

## Root cause (confirmed)

`TradeOutcomePublisher.publishClosedTranches()` is invoked only when reconciliation observes `beforeOpen > 0 && afterOpen === 0` using the in-memory venue snapshot **before** the REST reconcile fetch.

`GatewayUserPosition` stream events call `venue-state.applyPosition()` between reconciles. When a stop, target, or flatten closes the position, the stream often marks the instrument flat **before** the next reconcile runs. Reconcile then sees `beforeOpen === 0` and skips publication entirely.

Secondary gaps:

- `GLITCH_TOPSTEP_OUTCOMES_EXPORT_PATH` is not configured in the operator gateway `.env`;
- `trade_outcome.v1` carries realized PnL and fees only — no fills, slippage, MAE/MFE, buffer impact, or explicit exit reason;
- MAE/MFE is tracked ephemerally in Hermes `active-trade-state.json` but not persisted into the canonical outcome on close;
- NT parity gap: Glitch NT outcomes include MAE/MFE, R-multiples, and `close_kind`; `docs/PARITY.md` lists these as missing for Topstep.

## Objective

Make every attributable instrument flat transition publish exactly one deduplicated canonical outcome that Hermes can debrief into `trade_episode.v1`, with enough execution evidence for fills, fees, slippage, MAE/MFE, risk-normalized metrics, and buffer impact when provider data and protection attribution are available.

## Plan

### Phase A — Reliable flat detection (gateway, P0)

1. Track instrument open contract count at the last successful reconcile (`last_reconciled_open_contracts`).
2. On `GatewayUserPosition` / `GatewayUserTrade` events that reduce scoped exposure to zero, capture open tranches **before** mutating venue state.
3. Publish outcomes on the first authoritative flat observation from either reconcile REST or stream-driven flat transition.
4. Deduplicate by `intent_id` via `TradeOutcomeStore`.
5. Append `trade_outcomes_published` ledger event with `intent_ids` and trigger source (`reconcile` | `stream`).

**Acceptance A**

- PRAC round-trip produces at least one row in `data/trade-outcomes.jsonl` and `GET /outcomes`.
- `data/events.jsonl` contains `trade_outcomes_published`.
- Regression test simulates stream flat before reconcile and still publishes.

### Phase B — Hermes mirror and learning loop (P0)

1. Document and set `GLITCH_TOPSTEP_OUTCOMES_EXPORT_PATH` to Hermes `state/outcomes.jsonl`.
2. Verify `sync_gateway_outcomes()` appends new rows after flat.
3. Verify learning debrief produces `trade-episodes.jsonl` and `trade_episode_count >= 1` when `learning_eligible=true`.

### Phase C — Outcome enrichment v1.1 (gateway, P1)

Backward compatible: existing v1 fields remain required. New fields required when `learning_eligible=true`.

| Field | Purpose |
|---|---|
| `exit_reason` | `take_profit`, `stop_loss`, `manual_exit`, `flatten`, `reconciliation`, `unknown` |
| `fills[]` | Attributed provider trades: price, size, side, order_id, timestamp |
| `entry_price`, `exit_price` | Structural / fill attribution |
| `stop_price`, `target_price` | Planned geometry at entry |
| `quantity`, `side` | Closed size and direction |
| `slippage_ticks` | Planned vs fill when intent geometry exists |
| `mae_usd`, `mfe_usd` | Max adverse/favorable excursion |
| `mae_ticks`, `mfe_ticks` | Optional normalized |
| `initial_risk_usd`, `r_multiple` | Structural risk and normalized result |
| `buffer_impact_usd` | Delta of `hard_buffer_usd` entry → exit |
| `protection_confirmed` | Required for `learning_eligible` |
| `packet_id`, `snapshot_hash` | Link to decision packet |
| `evidence` | Sanitized order/trade IDs, publisher version |

`learning_eligible=false` when protection, attribution, MAE/MFE, or excursion metrics are incomplete.

**Acceptance C**

- Learning-eligible outcome includes fills and MAE/MFE when provider evidence exists.
- `docs/PARITY.md` canonical outcomes row updated for MAE/MFE/exit cause.
- v1-only consumers remain compatible (optional fields ignored).

### Phase D — Backfill (P2)

Idempotent script from SQLite + `Trade/search` for prior PRAC sessions; `learning_eligible=true` only when protection and fills are provable from retained evidence.

## Out of scope

- Inferring completed trades from balance or position disappearance alone.
- Hard deterministic flatten on `must_flat_utc` (TS-R3-02).
- Master/follower replication diagnostics (NT-specific).
- Counterfactual PnL for abstentions.
