# TS-R3-03 — Rich trade outcomes for Hermes learning

**Status:** open  
**Priority:** P1 learning parity  
**Gateway version target:** 0.1.3+  
**Profile contract:** extends `glitch.topstep.trade_outcome.v1` → **v1.1** (backward compatible)  
**Depends on:** TS-R3-01  
**Profile consumer:** `glitch-topstep-hermes-profile:GTHP-012`

## Objective

Publish completed-trade outcomes with enough intratrade and exit attribution detail for the Hermes learning supervisor to reach parity with Glitch NT debrief quality (MAE/MFE, exit cause, risk-normalized metrics), without requiring the profile to infer trades from balances or position disappearance.

## Gap vs Glitch NT

NT `glitch.hermes.trade_outcome.v1` (via `reconcile-hermes-outcomes.py`) includes sampled MAE/MFE, R-multiples, `close_kind`, and strict `master_learning_eligible` rules. Topstep TS-R3-01 ships minimal outcomes; `docs/PARITY.md` lists **Canonical completed outcomes — Missing (MFE, MAE, exit cause)**.

## Contract extension (`glitch.topstep.trade_outcome.v1.1`)

Backward compatible: existing v1 fields remain required. New optional fields become **required when `learning_eligible=true`**.

### New / expanded fields

| Field | Type | Purpose |
|-------|------|---------|
| `exit_reason` | enum | `take_profit`, `stop_loss`, `manual_exit`, `flatten`, `reconciliation`, `unknown` |
| `entry_price`, `exit_price` | number | Structural attribution |
| `stop_price`, `target_price` | number \| null | Planned geometry at entry |
| `quantity` | integer | Closed size |
| `side` | `long` \| `short` | |
| `mae_usd`, `mfe_usd` | number | Max adverse/favorable excursion during trade |
| `mae_ticks`, `mfe_ticks` | integer | Optional normalized |
| `initial_risk_usd` | number | Structural risk from entry stop × qty × tick value |
| `r_multiple` | number | `realized_pnl_usd / initial_risk_usd` when risk > 0 |
| `protection_confirmed` | boolean | Required for `learning_eligible` |
| `packet_id`, `snapshot_hash` | string | Link to decision packet |
| `evidence` | object | Sanitized order IDs, trade IDs, publisher version |

### `learning_eligible` rules (tighten)

Set `false` when any of:

- protection not confirmed at entry;
- attribution incomplete (missing entry order or exit trades in window);
- reconciliation gap or disconnect during trade;
- MAE/MFE could not be computed from authoritative fills;
- instrument/account mismatch.

System defects remain in outcomes with `learning_eligible=false` for operational review.

## Ponytail ceilings

- MAE/MFE from sampled position marks between fills if tick-level path unavailable — document sampling interval in `evidence`.
- Upgrade path: tick-accurate path when `projectx-evidence` journal has sufficient granularity.

## Acceptance

- Flat transition publishes v1.1 outcomes with MAE/MFE when fills exist.
- `learning_eligible=true` only when protection, attribution, and excursion metrics are complete.
- Profile `valid_outcomes()` accepts v1 and v1.1; debrief evidence includes new fields after GTHP-012.
- `docs/PARITY.md` row "Canonical completed outcomes" moves to **Implemented** for MAE/MFE/exit cause.
- No Hermes schema break for v1-only consumers (optional fields ignored).

## Out of scope

- Master/follower replication diagnostics (NT-specific).
- Counterfactual PnL for abstentions (remains decision episodes in profile).
