# TS-R4-07 — Session phase and stream-health evidence

**Status:** open  
**Priority:** P1  
**Issue:** [#85](https://github.com/GlitchTrader/glitch-topstep/issues/85)  
**Gateway version target:** 0.1.5+  
**Depends on:** TS-R3-02  
**Profile consumers:** `glitch-topstep-hermes-profile:GTHP-018`, `GTHP-019`, `GTHP-020`

## Objective

Publish labeled **session phase** and **stream health** in the decision packet so Hermes and profile workers can detect maintenance/reconnect without inventing calendar truth or relying solely on env stale skip.

## Planned fields

```json
{
  "session": {
    "phase": "regular | maintenance | asia | null",
    "phase_authority": "operator_configured | exchange_calendar | null"
  },
  "stream_health": {
    "quote_age_ms": 12000,
    "last_trade_age_ms": 45000,
    "trade_count_60s": 0,
    "reconnect_pending": false,
    "notes": []
  }
}
```

Nullable when unknown. `notes` must state provenance.

## Acceptance

- Fields in `glitch.direct.decision_packet.v2`.
- Regression tests; `docs/PARITY.md` row.
- No ENTER_* rejection on phase or stream_health alone.

## Stop line

Evidence only—no strategy gates, no auto-flatten on maintenance.
