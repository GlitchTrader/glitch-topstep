# TS-R3-04 — Daily economics mirror in decision packets

**Issue:** [#76](https://github.com/GlitchTrader/glitch-topstep/issues/76) (profile consumer: GTHP-017)  
**Priority:** P1  
**Depends on:** TS-R3-01, trade history reconciliation (TS-R2-06)

## Objective

Publish **labeled mirrors** of intraday PnL and program targets in the decision packet so Hermes can pursue daily profit and payout objectives **without inventing dashboard truth** and **without** Glitch rejecting entries based on PnL bands.

## Packet block

See `glitch-topstep-hermes-profile:docs/specs/GTHP-017.md` for `daily_economics` shape.

Minimum fields:

- `trading_day_id` (Topstep maintenance-to-maintenance boundary, operator timezone)
- `realized_pnl_usd`, `unrealized_pnl_usd`, `net_daily_pnl_usd`, `net_daily_pnl_pct`
- `nominal_size_usd` (from policy config)
- `calibration_band_pct` `{ low: 0.4, high: 2.0 }` (evidence defaults, not gates)
- `profit_target_remaining_usd` when eval target configured
- `authority` + `notes[]`

## Computation

- **Realized:** sum attributed closed trade PnL for current trading day from reconciled trades / outcomes.
- **Unrealized:** from current position mark and conservative equity (existing snapshot).
- **Net:** realized + unrealized; label as mirror.
- **Trading day:** reuse session calendar timezone and day boundary (`session-calendar.ts`).

## Acceptance

- Fields present in `buildDecisionPacket` when config enables `GLITCH_DAILY_ECONOMICS=true` (default true when inputs exist).
- Null fields when history incomplete; `authority` reflects uncertainty.
- Tests in `tests/packet-daily-economics.test.ts`.
- `docs/AUTHORITY.md` unchanged: block is evidence, not execution gate.
- `docs/PARITY.md` note when operator validates against dashboard.

## Out of scope

- Rejecting `ENTER_*` when `net_daily_pnl_pct` exceeds band (forbidden).
- Guardian auto stop-tighten or flatten for profit floor (GTHP-017 stop line).
- Official Topstep payout eligibility without dashboard override.
