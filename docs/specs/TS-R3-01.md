# TS-R3-01 — Canonical completed trade outcomes

**Issue:** TBD  
**Gateway version:** 0.1.2+  
**Profile contract:** `glitch.topstep.trade_outcome.v1`

## Objective

Publish attributable completed-trade outcomes when the configured instrument transitions from open to flat, without making the Hermes profile infer trades from balances or position disappearance.

## Contract

Append-only `trade-outcomes.jsonl` in the gateway data directory with records matching `glitch.topstep.trade_outcome.v1`.

Required fields:

- `outcome_id` (`outcome:<intent_id>`)
- `intent_id`
- `account` (sanitized alias)
- `instrument`
- `entry_utc`, `exit_utc`
- `realized_pnl_usd`, `fees_usd`
- `learning_eligible` (true only with proven protection, attributable entry order, and provider trades in window)

Optional `attribution` block records protection status and trade count.

## Surfaces

- `GET /outcomes?limit=N` — authenticated page of recent canonical outcomes
- optional mirror via `GLITCH_TOPSTEP_OUTCOMES_EXPORT_PATH` (append to Hermes `state/outcomes.jsonl`)
- Hermes cycle calls `/outcomes` each minute via `sync_gateway_outcomes()`

## Acceptance

- flat transition on configured instrument publishes one outcome per open tranche intent not yet recorded;
- duplicate intent_id is never re-published;
- incomplete attribution sets `learning_eligible=false`;
- profile learning worker consumes mirrored/synced outcomes without schema changes.
