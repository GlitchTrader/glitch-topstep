# TS-R4-06 — Amendment tightening and market-side bounds

**Issue:** [#75](https://github.com/GlitchTrader/glitch-topstep/issues/75)  
**Priority:** P1 (Phase A amendments)  
**Depends on:** TS-R4-00

## Objective

Enforce **factual execution boundaries** on `MOVE_STOP` and `MOVE_TP` before `modifyOrder`. No cognition vetoes; Hermes receives attributable rejection codes.

## Phase A — amendments (this spec)

### Tightening only

| Side | MOVE_STOP | MOVE_TP |
|------|-----------|---------|
| Long | `new_stop_price` ≥ current venue stop | `new_take_profit` ≥ current target |
| Short | `new_stop_price` ≤ current venue stop | `new_take_profit` ≤ current target |

Reject with `stop_would_widen` or `target_would_widen`.

### Market / entry geometry

- **Long stop:** reject `stop_wrong_side_of_market` when `new_stop_price >= bestAsk` (marketable through spread).
- **Short stop:** reject when `new_stop_price <= bestBid`.
- **Long target:** must stay above `averagePrice` (`target_wrong_side_of_entry`).
- **Short target:** must stay below `averagePrice`.

Breakeven stops at or inside the spread are allowed (stop below ask for long).

### Implementation

- `src/execution/amendment-safety.ts` — pure validation
- `src/execution/coordinator.ts` — called from `handleProtectiveAmendment` after tick alignment
- Tests: `tests/amendment-safety.test.ts`, coordinator cases in `tests/position-management.test.ts`
